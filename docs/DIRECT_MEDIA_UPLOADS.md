# Direct media uploads on Free hosting

Read SERVICE_OWNERSHIP.md first. Core owns `/uploads/direct`; clients send it small authenticated metadata requests; completion reads bounded objects from R2 for validation. Publication remains on the feature's owning service. All roles share the same Redis, R2 bucket and JWT configuration. Do not add a Core byte proxy or embed R2 credentials in a client.

## Protocol

1. Authenticated `POST /uploads/direct` with `{purpose, contentType, sizeBytes, filename, conversationId?}`. Purposes: post, story, story-overlay, reel, avatar, banner, comment, chat. Chat also checks current membership, block and media permission. The user comes from the verified JWT, never the body.
2. Response is `{mode:'direct', uploadId, url, headers}`. PUT the exact Blob directly to `url`, with the supplied headers, credentials omitted and no application Authorization. Browsers supply Content-Length automatically. The signature lasts180seconds and binds Content-Length, Content-Type and If-None-Match. Only local storage can explicitly return `{mode:'proxy'}`; errors never authorize fallback to Render.
3. Authenticated `POST /uploads/direct/:uploadId/complete` returns `{uploadId,url,contentType,sizeBytes,kind,duration?,width?,height?,filename?}`. The server verifies actual R2 HEAD, reads at most the admitted size (20MiB maximum), validates media container/packets and fully decodes video/audio with bounded ffmpeg. Images are strictly decoded and re-encoded by the existing image processor before a bounded server PUT; video/audio use conditional R2 CopyObject after validation. Final keys differ from staging keys. Owner, purpose and conversation metadata are written by the server. Completion is idempotent and serialized against cancellation.
4. Feature APIs receive `uploadId` instead of a file. Posts receive their existing `media` JSON array with completed URLs. Stories also receive an `overlayUploads` JSON map from layer ID to completed upload ID. Consumers recheck owner, purpose and chat context against trusted object metadata. External post GIFs have an explicit provider allowlist.
5. Best-effort `DELETE /uploads/direct/:uploadId` cancels an unfinished intent. It never deletes a completed object that a publication may already reference. Failures do not refund reserved byte/request allowance. `GET /uploads/direct/quota` exposes the caller's admission allowance.

Use the shared `prepareDirectUploadForm` transport. Native form builders supply their tracked entries; never depend on React Native FormData internals. Web clients re-encode non-GIF images with canvas; native clients use the existing Expo image manipulator. This strips image metadata in normal client flows. Server image re-encoding also strips metadata and preserves supported animation within existing frame/pixel limits. These small normalized image PUTs still consume Render outbound bandwidth; direct video/audio CopyObject avoids a second outbound media transfer.

Generic chat files, including encrypted attachments, use application/octet-stream and attachment disposition; encrypted payloads are not inspected as plaintext. Existing story reference messages are generated by StoriesService only after story visibility checks; client-supplied messages cannot select that trusted internal path.

## Admission limits

| Limit | Default |
|---|---|
| Image / audio / video or generic file |5 /10 /20MiB|
| Reels container duration / dimensions |60seconds /1920pixels per dimension|
| User daily / monthly bytes |64 /256MiB|
| Global daily / monthly bytes |256MiB /2GiB|
| User / global daily reservations |40 /400|
| User / global active reservations |3 /20,15minute lease|
| Bucket admission ceiling |8GiB, with at most10inventory pages|

The video check combines bounded MP4/WebM metadata inspection with full container/packet validation and ffmpeg decoding, using the existing decoder concurrency and timeout limits. WebM without a usable duration or oversized metadata is rejected. MediaRecorder outputs can lack duration; keep the original supported file rather than inventing a duration or claiming success. Reels play directly; heavy transcoding is disabled unless VIDEO_TRANSCODE_ENABLED=true on appropriate compute.

Admission is an atomic Redis operation and fails closed when Redis is unavailable. Counters are conservative and reset in UTC. The existing Redis LRU policy can evict counters; they are not a durable total-storage accounting system. Inventory checks precede signing after reserving allowance, so repeated rejected requests cannot endlessly enumerate R2. Inventory failures deny new uploads. This is application admission control, not a guaranteed provider billing cap or unlimited storage.

## Bucket and deployment configuration

Keep the scoped object-only key in server variables on all four roles. R2 CORS allows only the deployed desktop and Expo Web origins, GET/HEAD/PUT, and content-type, if-none-match and range headers. Expose ETag and range/length response headers. A new frontend origin needs an explicit CORS update.

The `_incoming/` prefix is temporary staging, publicly accessible through an unguessable object key, not a private quarantine. Its lifecycle deletes objects after one day. Successful completion retains the staging object until lifecycle expiry so the still-valid PUT cannot recreate it after deletion. Publication uses a different final key; the staging lifecycle must never match `media/` or `reels/`. Keep the existing multipart-abort rule. Do not enable paid storage classes or Workers under a zero-dollar budget.

Before a coordinated release, stage Vercel production builds without domain assignment. Deploy compatible APIs before promoting those clients. Production sets DIRECT_UPLOADS_REQUIRED=true; legacy multipart byte uploads and resumable Render chunks are then rejected. Local chunk compatibility remains user-bound and limited to four5MiB chunks. No installed native builds currently require the old upload API; future native releases need an explicit compatibility plan.

PostgreSQL/Redis/media warnings are recorded in server logs. Render bandwidth, R2 public reads/operations, provider restrictions and cold starts remain external limits. R2's public development domain is rate-limited; a cached custom domain requires an existing domain. Do not promise uninterrupted month-long service based only on a user count.

New features such as decorations, Family Center and nameplates keep their ordinary APIs on Core. A new media purpose needs an explicit server allowlist/policy, matching shared transport type and a consumer ownership check; do not reuse an unrelated proof to skip authorization. Messenger channels/bots keep APIs and persistent work on Messenger, with their own channel/bot access checks. `sendStoryReference` is an internal story-only path, never a general client upload escape hatch.
