# Component reference

For when to choose each component and correct/incorrect composition examples, see [component usage](component-usage.md). Contrast and touch geometry need the [readability checks](readability.md) in addition to the visual recipe.

Recipes below describe existing defaults; `className`, feature wrappers and native element props can override them. Source links are the implementation reference, and the [inventory](web-design-inventory.json) retains conditional class/style expressions. Pixel conversions assume the web's default 16px root.

## State inventory for reuse

For each component implement default, hover (pointer platforms), focus, pressed, disabled, selected and pending states where applicable. Content components additionally need loading, empty, failure/retry, unavailable/deleted and overflow states. Chat adds sending, failed/retry, sent, delivered/read, replies, reactions, selection, recording and blocked states. Media adds buffering, paused/playing, muted, autoplay blocked, permission denied and unsupported/error states.

These are acceptance requirements for future reuse; the existing web implementation is not universally complete. Shared controls now implement the keyboard and semantic patterns described above, while some feature lists still do not render a separate error state. The [executable reference](scenarios.md#executable-reference-coverage) demonstrates combined control, overlay and feedback states. Preserve useful behavior and address remaining gaps explicitly.
