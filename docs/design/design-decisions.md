## Continuity implementation recorded on 2026-10-04, updated on 2026-10-05

Post actions use an absolute React optimistic target while the existing TanStack mutation updates the cached base. A relative toggle was applied again when React rebased on that already updated cache, showing the wrong selected state while the request was pending. The held-response tests exercise selected state before and after the refetch; server/cache mutation ownership remains with the existing hooks. Rapid concurrent mutations and production recovery remain separate coverage.

Feed keeps only unsent text in session memory. Publication clears the submitted revision, so an older response cannot erase a newer draft or text from another account. Back/Forward positions are bounded to 50 router entries; restore waits for content height for at most five seconds and yields to user scroll input. The feed observes changing layout above its virtual list to keep its scroll margin current.

Chat preserves input immediately rather than depending on a reply-state debounce before navigation. Its last 20 virtual scroll snapshots are session memory and clear on account reset; a generation check prevents outgoing cleanup from repopulating an account's cache. Retry keeps the existing message ID and sequence through HTTP fallback and returns focus immediately to the named composer. Conversation rows use a native opening button beside their separately named action menu. Keyboard focus reveals that menu, and returning from detail restores focus to the opening button. Live following uses proximity to the actual bottom rather than the visibility of the one-screen scroll button. Wheel, touch, scroll-region pointer and upward keyboard input cancel only a pending live-pin target; automatic row measurements must not be mistaken for user input. While following remains active, changes to measured total height or the scroll viewport height realign the last row on the next animation frame, after React commits the size container; a ResizeObserver on the committed size container and viewport also handles later geometry changes. While live following is active, a scroll event more than 20px from the bottom schedules realignment to catch late browser offset corrections after size has settled. Pending alignment yields to user input. Ref measurements can otherwise flush the effect against the previous DOM height. An explicit older-message jump turns following off until the reader returns to the bottom. Explicit reply/search/pinned jumps retain their target. The named history region is keyboard-focusable; PageUp can browse history independently of the composer. The delayed smooth adjustment runs only for an actual music-dock offset change, avoiding a second initial positioning command. This avoids later measurements or send acknowledgements pulling the reader down. These choices preserve current storage/protocol contracts; they do not establish production exactly-once delivery or native platform behavior.

## Updating a decision

Link the changed runtime owner and actual verification result. Explain the trigger, intentional platform difference and remaining limitation. Preserve token units, state semantics and stored theme/layer/font IDs. Keep a proposal marked Proposed while dependent implementation or verification is pending; document partial implementation by scope instead of upgrading the whole entry. Source generation, documentation link checks and screenshots serve different purposes and cannot substitute for runtime or platform evidence.
