# Actual screen captures

These canonical Windows Chromium captures use the real application routes with fictional multilingual API fixtures, blocked external HTTP/WebSocket traffic, fixed time and reduced motion. They are produced by [screen tests](../../apps/web/e2e/design/screens.spec.ts), rather than mock screen compositions. Feed/Profile content captures include the full page; Messenger preserves the actual viewport and checks input/Send geometry.

Run the commands in [scenarios](scenarios.md#executable-reference-coverage) to compare against these images. Tests serve the built production app through Vite preview; rebuild after source edits. To update them after a reviewed rendering change, run `pnpm --dir apps/web test:design --update-snapshots`, then inspect every changed image and attached readability report. Never generate missing baselines automatically in CI.

On 2026-10-05, eight Feed/Stories baselines were reviewed and refreshed after switching the harness from development Vite to production preview. Differences were confined to the caught-up SVG checkmark, story sound icon and caption text rasterization; layout, content and state assertions remained unchanged. Screenshot tolerances were not widened. See the [validation log](platform-validation.md) for passing runs and limitations.

These images reflect Windows font metrics. They do not establish pixel parity on macOS, Linux, iOS or Android. Native clients still need device screenshots, keyboards, safe-area and assistive-technology checks from [platform guidance](platforms.md).
