# Screens and layouts

## Responsive vocabulary

The installed Tailwind defaults are `sm=40rem`, `md=48rem`, `lg=64rem`, `xl=80rem`, `2xl=96rem` (640/768/1024/1280/1536px at a 16px root). Prefixes are minimum-width conditions; `max-md` applies below md. These are web defaults, not native device classes. Several components use arbitrary breakpoints and JavaScript resize calculations; the [inventory](web-design-inventory.json) records the actual expressions.

Containers: `max-w-md=448px`, `lg=512`, `xl=576`, `2xl=672`, `3xl=768`, `7xl=1280`. Layouts mix rem-based containers with explicit pixels and viewport units. Keep actual route behavior when matching web; use available width when adapting native.

## Application shell and navigation

[App](../../apps/web/src/app/App.tsx) composes the sidebar, route content, friends sidebar, global media player and overlays on `#070709`. Centered route wrappers use 32px vertical padding, 16px horizontal gutter and a 672px (`max-w-2xl`) content cap. Profile has its own wrapper. Main content reserves 288px (`pl-72`) when the sidebar is expanded and 96px (`pl-24`) when collapsed. Spotify dock reservation is 56px minimized or 112px expanded. Sidebar visual widths and main content reservation are intentionally different values.

## Messenger and calls

[Messenger](../../apps/web/src/pages/Chat/Messenger.tsx) and [StandaloneChatPage](../../apps/web/src/pages/Chat/StandaloneChatPage.tsx) compose chat-specific panels rather than the centered feed recipe.

The main Messenger uses one list/detail section below 768px; Back returns to `/messages`. Desktop retains resizable side panels. Narrow header actions wrap and the message input takes its own row. Main Feed/Profile remove the desktop navigation gutter at that breakpoint and provide a mobile navigation header with the existing navigation drawer. See [actual captures](screen-captures.md), [readability findings](readability.md) and [proposed native/desktop flows](prototypes.md) for scope and verification limits.

## Music and global player

[MusicHubPage](../../apps/web/src/pages/Music/MusicHubPage.tsx) is a separate dense media workspace. Locate its feature components in the inventory by `features/music/`.

The library panel uses `#121216`/85, collapsed72px and resizable expanded width; 300ms cubic-bezier(.16,1,.3,1), no transition during resizing. Now-playing sidebar is xl+ only, collapsed20px, `#111116`/85. The top navbar is64px with `#09090d`/80, 48px search/home controls; central width limits720/820/920px and search min380px. These desktop measurements require adaptation before reuse on phones.

Overview grids vary from 1→2(sm)→3(lg) compact rows and 2→3(sm)→4(md)→6(lg) covers. Cards use12px padding/16px corners, white/3→7 hover and -4px hover lift; 40px purple/indigo play controls appear on hover. Touch clients need persistent access to playback actions.

[SpotifyBottomDock](../../apps/web/src/widgets/player/SpotifyBottomDock.tsx), [SpotifyMobilePlayerSheet](../../apps/web/src/widgets/player/SpotifyMobilePlayerSheet.tsx), lyrics, queue, search, jam popovers and [SpotifyGameModePlayer](../../apps/web/src/widgets/player/SpotifyGameModePlayer.tsx) define additional glass/media states. Dominant cover colors are dynamic, so a finite palette cannot describe every rendered player background. Preserve artwork-driven treatment with readable controls and opaque fallback.
